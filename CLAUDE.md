# website-builder

## Design skills

For all website and UI work in this repo, use these three project skills together:

- `minimalist-ui`: the visual style (warm monochrome, editorial type, flat bento grids, muted pastels).
- `redesign-existing-projects`: when changing pages that already exist, audit first and upgrade in place instead of rewriting.
- `full-output-enforcement`: ship complete files and components, with no placeholder code.

When two of them disagree on a visual choice (fonts, icons, colors, shadows, radii), `minimalist-ui` wins.

### Motion, interaction and robustness (Emil Kowalski's skills)

Use these alongside the three above:

- `emil-design-eng` and `animate`: how to build animations and interactions (easing, duration, which properties to animate, interruptions).
- `apple-design`: gesture-driven UI, springs, drag, swipe and sheets. Ignore its suggestions on glass materials, system fonts and replacing borders with blur, since `minimalist-ui` decides those.
- `mobile-native`: make pages feel right on phones (100vh, tap highlights, input zoom, safe areas).
- `find-animation-opportunities`, `improve-animations`, `animation-vocabulary`, `ask-sonner`: use when the task calls for them.
- `review-animations`, `pick-ui-library`, `prototype`, `break-ui`: run these when asked, by name.

`minimalist-ui` decides how things look. Emil's skills decide how they move and behave.

Do not use `design-taste-frontend`, `high-end-visual-design`, or `industrial-brutalist-ui` unless asked. They are installed but conflict with the minimalist style.
